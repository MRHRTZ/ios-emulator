# Screenshots

Screenshots will be added after the revised UI and guest behavior are verified.
Capture the actual running application; do not use mockups as boot evidence.

Planned examples: native dark/light window, interactive home screen, settings,
and a rendered test webpage once Safari's blank content is fixed. Label kernel
version, CPU/RAM settings and known limitations. Keep private data, network
captures and Apple firmware out of screenshots and repository uploads.

The GUI Screenshot button exports guest pixels. Host UI evidence should capture
the complete emulator window separately.
